# Actor identity, zero and unknown

The supported source is Rebuild `4099e2c000c3c550516760b9c1241595aac9aceb`. Its [World allocator](https://github.com/Doddler/RagnarokRebuildTcp/blob/4099e2c000c3c550516760b9c1241595aac9aceb/RoRebuildServer/RoRebuildServer/Simulation/World.cs#L919-L931) wraps its counter to zero and returns it when unused. Players, monsters and NPCs can therefore have actor ID `0`. The client retains signed-int32 bounds (`0..2147483647`) rather than confusing that allocation value with absence. Other identifiers keep their individual bounds.

| Supported field | Contract | Sentinel / limitation |
| --- | --- | --- |
| MemoryPack spawn; EnterServer own ID | Nonnegative actor ID | Local unannounced identity is `null`; `IsMainCharacter` does not establish self. |
| Walk, stop, position, removal, death, healing, resurrection | Nonnegative actor ID | Only a currently observed actor is updated. A new own character requires Enter plus an appropriate kind-0 spawn. |
| Status apply/remove, targeted notification, cast start/extend/stop | Nonnegative actor ID | Cast target `-1` means absent. Unknown observations remain unavailable, including negative predicates. |
| Normal attack result | Nonnegative target; attacker `-1` or nonnegative | `-1` is no attacker. A generic movement fence has `null` target, never synthetic actor zero. |
| Skill execution/impact/masked result | Nonnegative source; direct optional attacker/target `-1` or nonnegative | Exact source, skill, level, mode, ground coordinate, world and observed lifetime still gate receipts. Indirect damage is not cast success. |
| Pickup result | Picker `-1` or nonnegative; positive drop ID | Actor zero does not relax drop IDs. |
| ChangeTarget 33 | Positive ID establishes a known eligible selected actor; zero clears | [SendChangeTarget](https://github.com/Doddler/RagnarokRebuildTcp/blob/4099e2c000c3c550516760b9c1241595aac9aceb/RoRebuildServer/RoRebuildServer/Networking/CommandBuilder.cs#L1215-L1222) writes `target?.Id ?? 0`; the official client clears selection at zero. This packet cannot distinguish selected actor zero from absence. Candidate and explicit lifetime selection can independently use zero. |
| Attack, targeted item and actor-skill requests | Nonnegative actor target | Untargeted item target is omitted or `-1`. Runtime visibility, eligibility, range/LOS, resources and one-action ownership still apply. |

| Bag, item, drop, skill, status-condition, class/species and local incarnation IDs | Owning positive constraints retained | Equipment empty slots, ammo and other sentinels keep their existing field-specific meanings. |

The field evidence comes from pinned `Networking/CommandBuilder.cs`, `Simulation/EntityComponents/Player.cs`, `Simulation/Parties/Party.cs`, and `PacketHandlers/Character` attack/skill/item/NPC handlers. `WorldObject.Id = -1` is the unassigned server value, not an allocated actor. Party member IDs and party IDs are separate domains.

`BotEngine.playerId` is nullable announced identity; `engine.player` is the ready observed kind-0 entity. Enter resets old world and character state. Post-enter full stats/skills/inventory may precede own spawn and are retained as initialization, but cannot authorize an action, self predicate, resource/cast receipt or social echo without the own entity. Map refreshes require a fresh own spawn; disconnect and character re-entry discard old authority. No name, first actor, `IsMainCharacter` flag or default zero substitutes for Enter.

The existing actor-observation world UUID and local incarnation bind dispatched feature actions, explicit world-actor requests, observed NPC workflows and canceled receipts. NPCs with source-default zero HP retain identity records while their status/cast predicates remain unsupported. A new spawn replaces both actor stores so an old NPC entry cannot survive cross-kind ID reuse. Replacement also discards normal-attack/pursuit and earned skill-kill evidence for that actor; any cancellation retains a bounded, targetless movement fence that a late attack cannot acknowledge. Historical positive-ID focus-only contexts retain their prior guard behavior; newly supported zero requires independent observed NPC identity. Removing/replacing self or an explicit target, or resetting its world, prevents late data from completing that earlier action. Social echoes are canceled when the observed own lifetime disappears or changes, preserving cooldowns and repeated-message ambiguity. Canceled NPC-end and vending receipts require the captured lifetime as well. Only the engine-owned respawn transition may confirm its expected new own incarnation; a same-map clear alone cannot do so. Targetless Stop/movement ownership remains targetless. UI actor inputs begin blank: omitted item target stays omitted, while explicitly entering `0` survives validation and serialization. Imported observed-actor references still require explicit rebinding after departure/reset.

The wire has no request ID or actor incarnation. An identical late packet arriving after a server ID is reused cannot be perfectly distinguished from fresh data for that current ID. Local receipts never silently rebind to the new lifetime, and no stronger wire correlation is claimed.

The bounded observation table reserves capacity for announced self while its live record is absent, including death and loading. Field admission waits for an observed living own lifetime; automatic target selection skips actors whose observation could not be retained within the cap. Neither ordinary attacks nor skills may dispatch with an uncaptured identity. Temporary loss of own observation retains requested run intent and waits, rather than throwing from the automatic action scheduler.

Proof uses literal/source-shaped synthetic packets, controller/observation/UI tests, shared TypeScript/Rust request fixtures, and local build checks. There is no deployed allocator-wrap proof and no live social-send test. The change does not force allocation wrap, add social automation or loosen the verified build boundary.

The integrated 2026-10-02 release passed 1,320 TypeScript tests, 42 Rust tests, frontend/bridge build, typechecking, Clippy, formatting and two independent reviews. One Keychain test remained intentionally ignored. All nine routing benchmark outcomes, search counts and route hashes matched the preceding `ec34f05` release. Native ARM64 packaging and strict ad-hoc signature verification passed. A fresh session-only login and 71-second Field 8 run confirmed three defeats and five pickups, with zero deaths and final HP 161/161. Client Stop returned Ready at `(139,331)`. This verifies ordinary live combat compatibility; actor-zero allocation, observation-cap exhaustion, reused lifetimes and late-reply cases remain source-shaped synthetic proof.
