# Manual memo slots

The Travel panel shows exactly four server memo slots. **Unknown** means no complete readback has been observed; **Empty** is an explicitly absent server record. Select slot 0–3, click **Preview current location**, inspect the previous value and captured current map/cell, then click **Save once**. An already identical slot reports **Already current** and sends nothing. Changing the selection does not save. There is no Enter shortcut, deletion, arbitrary destination, automatic memo, warp casting or replay.

Saving requires a fresh compatible connected living own character, an independently observed world/actor incarnation, observed **learned Warp Portal (skill 55)** level greater than the slot index, explicit pinned **CanMemo** permission and a verified walkable current cell. Granted skills do not satisfy the prerequisite. Missing map metadata is unknown; field/town mode and collision data never imply permission. The generated map catalog contains **272 maps, 111 with CanMemo** from pinned `Maps.csv`, separately from the 231 published navigation grids. For example, pinned Prontera town permits memo, while Payon dungeon does not. Both permission and actual current-cell walkability must be available.

All other action owners must be stopped or settled: field/return travel, supply, emergency escape, social, NPC service/workflow, routine, resource/cast/equipment receipt and accepted or outstanding movement. The controller reuses the engine's stationary/action guard. A memo-specific outstanding-walk fence additionally survives Stop and bounded engine waits; an older own position/attack cannot release an unacknowledged explicit walk. Its matching unlocked accepted path must be observed and settle at its exact end cell, or a new world/character session must establish fresh readiness. Interrupted paths remain unavailable until fresh physical position is observed; Stop alone is not that proof. Preview binds world UUID, observed actor ID/incarnation, socket generation, memo revision and physical current map/cell. Save revalidates those guards. Stale preview, changed skills, new state, Stop, session, socket or character changes require a new preview. Actor ID 0 uses the same ready-own gate as other IDs: an Enter announcement and an observed living kind-0 actor with a current world/incarnation. Pre-Enter actor 0 and post-Enter initialization or memo readback before own spawn provide no dispatch authority; see [actor readiness](ACTOR_IDS.md).

The only outgoing bytes are **opcode 94, u8 slot**. Map and coordinates are preview guards, not a requested destination. The pinned server chooses its own current physical cell. No SP, zeny or item cost is claimed: this source handler writes memo state and sends observations without a verified deduction. Client prediction and actual server position may still differ; a different readback stays uncertain.

**Sent** means one transport dispatch only. **Notified** requires opcode 91, `ServerEvent.MemoLocationSaved` **8**, the exact selected slot and complete empty trailing string. **Confirmed** additionally requires a subsequent complete opcode 94 containing all four slots: the selected slot must equal the captured current map/cell and every untouched known slot must match the preview baseline. Initial snapshots, partial/truncated data, unrelated messages/errors, wrong/duplicate notifications, wrong ordering, unchanged readback and contradictory untouched slots do not confirm a write. A full snapshot following Enter can precede own spawn; it populates known slots but does not authorize dispatch.

The **10-second observation window** is an app policy. Timeout, clock changes, Stop, character/world/socket replacement or an uncertain send cancel the intent without replay; cancellation cannot undo a transmitted write. Uncertainty blocks further action owners until a fresh full snapshot reconciles known state or a new connection establishes fresh state. A same-connection Enter, character identity or own-incarnation replacement invalidates slot knowledge while retaining a sent/held fence; it cannot stand in for a complete readback. Reconciliation never claims that a canceled attempt caused the observed value. No request IDs exist. Identical slot/map/cell attempts cannot be uniquely attributed, so their matching readback remains **Uncertain**; at most 128 fingerprints are kept in memory and budget exhaustion disables future correlation. Fingerprints survive local Stop, world and character resets. A new page does not restore any intent. Preview, selection, receipts and observation fingerprints are absent from profiles, saved login, routines, workflows and reconnect persistence.
