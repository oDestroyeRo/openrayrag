# Game input ownership

Opening inventory, skills, equipment or another local game panel does not pause a requested field run or macro. Repeated pointer and keyboard input cannot starve new combat or pickup decisions. Incoming confirmations, skill motion, cooldowns, accepted movement and finite run allowances continue. Manual input does not look like Mac sleep, replenish the run budget, or retry a resource action. Real timeout, health, connection and session-limit failures keep their existing safeguards.

The official socket's outgoing binary opcode separates local input from gameplay. Official gameplay preserves requested automation; trusted movement commands allow a short, bounded reconciliation window for the current own actor's movement. The bot waits for observed movement to finish, then selects a fresh route or target. Unhinted bot movement still requires verified geometry and receipt ownership. The allowlist is pinned to Rebuild `4099e2c000c3c550516760b9c1241595aac9aceb`; unknown opcodes do not acquire authority. Only the current verified game socket with its own observed ready actor is classified. The raw login handshake has no opcode framing and is never inspected, including after reconnect. Character entry, readiness, Ping, chat, emotes, facing and text queries are excluded; strings and Blobs are not inspected. The observer reads only the first byte, never stores or logs packet bodies, and forwards each original official send once. Companion's own transports call the native socket prototype and bypass the hook.

Every trusted official input still retires unsent memo/socket previews. It also taints a sent socket operation, which needs a fresh full inventory readback to reconcile without attributing the old result. A sent memo keeps its full-readback fence. Explicit Companion Stop cancels run intent; it does not undo a transmitted action. Real manual gameplay can leave an interrupted cast or economic operation uncertain rather than fabricate success or repeat it.

Same-character manual map changes retain field intent and safe unsent macro travel/service preparation. Replanning keeps the original trip, run counters and macro/step deadlines, and retires old asynchronous planners before accepting their results. A sent Database teleport or economic action keeps its existing ordered receipt and uncertainty fence. Official refining uncertainty remains visible and blocks Tools and updates, but does not cancel an already requested field run. Companion-owned refining receipts still block competing automation. Reconnect or character replacement cannot resume a retained macro.

An official NPC conversation blocks new physical actions on the pinned server (`Player.CanPerformCharacterActions` checks `IsInNpcInteraction`). The bot retains its request, processes receipts and advances deadlines while waiting, then resumes after the interaction closes. It does not automatically choose dialogue options. Inventory, skills and Database panels alone do not impose this server restriction. Companion Tools retain their idle-only admission.

Observed own casting fences new physical actions. Combat, search, loot, recovery, detached commands and travel wait before reserving a scheduler action, movement leg or resource budget. Existing movement, receipts and absolute deadlines continue. Field intent and finite allowances are retained; the wait itself does not issue Stop, restart a run or reset its death count. Client Stop remains available, and the existing HP emergency-escape policy keeps its explicit preemption behavior.

The shared `BotEngine.observedOwnCastSettled()` fence belongs to the current connection, world and own actor incarnation (including actor zero). Targeted/area CastStart 24/25 records skill, level and target/self/ground shape. Timers, CastExtend 26, local Stop, generic errors and unrelated packets cannot establish completion. StopCast 27, a matching supported direct skill execution, or validated identity invalidation retires the fence. ResetMotion 111 does so only for the currently observed self CounterAttack 31: the pinned `CounterAttackHandler.Process` is its sole producer, called after `CombatEntity.FinishCasting` clears `IsCasting`. That packet contains just the caster i32; it does not acknowledge an item, skill request, budget or other transaction. Published actor predicates retain their separate observation semantics.

Cast packets contain no request identifiers. Matching uses the observed actor lifetime and execution shape with the pinned server/socket ordering; it is not exact request correlation. The pinned unmarked procs can mimic self Increase Agility 42 level 1, targeted Decrease Agility 43 levels 1/3, and targeted Jupitel Thunder 96 levels 3/5/10. Those exact result shapes do not retire the cast fence. Equipment absence cannot disambiguate them because queued procs survive equipment changes. Generic failures and missing completion also retain the fence.

A later current-own StartWalk is availability evidence: the pinned `WorldObject.TryMove` queues or rejects movement during casting, and `Map.StartMove` is the StartWalk producer. It releases only this readiness fence, leaving resource and skill receipts untouched. Position updates and physical Stop are not equivalent evidence. The wait reason explains that walking in game after the cast finishes can confirm readiness; Companion sends no probe action. StopCast or a validated world/actor/connection replacement also retires the fence. Synthetic own-zero/nonzero fixtures exercise the six action paths, wrong source/shape/skill/level, stale connections, CounterAttack, unmarked procs, availability-only StartWalk, unchanged budgets, finite deadlines and Stop; these checks do not establish deployed-game behavior.

Source evidence: the pinned `RebuildClient/Assets/Scripts/PlayerControl/CameraFollower.cs` toggles skills at line 2035, equipment at 2048 and inventory at 2052 locally. Space calls StopPlayer at line 2001. `RebuildClient/Assets/Scripts/Network/NetworkManager.cs` writes the PacketType opcode first and sends the exact byte buffer (lines 478–506); `RoRebuildServer/RebuildSharedData/Networking/PacketType.cs` defines the allowlist IDs. This establishes the source contract, not deployed input or network proof.

Synthetic controller and bridge tests cover the normal late Fire Bolt opener result, own actor zero, new pickup decisions during repeated panel input, official movement and map continuity, recovery-item and automatic ammo receipts, real unconfirmed-item timeout, retained session limits, external refine/NPC ownership and explicit Stop. Deferred-planner fixtures verify late completion/rejection cannot cancel a retained trip. The bridge tests exercise the installed listeners and socket override, auth/query exclusions, active/build gates, native-prototype bypass and hook failure without a repeated official send. No live input, account action or native app launch is performed by these tests. Live evidence is recorded separately in [issue #108](https://github.com/oDestroyeRo/openrayrag/issues/108).
