# Local saved login

Sign-in is session-only by default. Selecting **Save login on this Mac** stores one account, password, character slot and app-open sign-in preference in the native Tauri application data directory, under `login/profile.json`. On macOS this is normally `~/Library/Application Support/com.rayrag.companion/login/profile.json`.

The `login` directory uses permission 0700 and the file uses 0600: access is restricted to the current macOS user. The application does not encrypt credentials. Other software running as that user, administrators and backups may read the file. No colocated encryption key is used.

The app does not read, migrate, update or remove an earlier macOS Keychain entry. Save credentials once with the new local option if you want persistent sign-in. **Forget local saved login** removes the local profile, its app-open preference and a private leftover temporary write. It does not cancel an already claimed login or discard the current session's reconnect credentials. Stop cancels pending sign-in/retries; closing the game clears session memory.

Native metadata returns only username, character slot and app-open preference. Passwords are passed once to the verified official game page when explicitly queued, never returned to the controller or stored in browser storage, bot settings or profile exports. The existing generation, account, character, page and socket binding remains in place for reconnection.

Native reads accept at most 4096 bytes and validate the complete profile schema. Descriptor-relative operations reject symbolic links in every directory component, nonregular files, hard links, wrong owners, nonprivate store/file permissions and existing macOS extended access lists. Newly created directories and temporary files have inherited access lists cleared and verified before credentials are written. An unreadable profile does not enable automatic sign-in; the UI offers Forget or manual entry. Unsafe paths remain rejected even for Forget.

Writes serialize concurrent app processes with a nonblocking directory lock, create a private temporary file, sync its contents, then rename it over the profile atomically and sync the directory. Newly created directory entries are synced in their parents. Failed partial writes preserve the preceding profile and remove the private temporary file. A crash before replacement may leave a private temporary file; a later successful save or Forget clears it. Read/Forget do not create an absent store. Errors contain no OS paths, profile bytes or credentials.

Synthetic native tests cover persistence, atomic old-inode preservation, permissions/access lists and inheritance, schema/corruption/size bounds, parent syncing, failure cleanup, symlink/nonregular/hard-link rejection, lock contention and Forget. Actual main-window form tests cover opt-in defaults, disclosure, metadata-only startup, saved-slot automatic login, native password reuse and unreadable-profile recovery. Existing one-shot/session/reconnect tests remain part of verification. No real saved profile, Keychain, account or app launch is used by these tests; native UI and live game proof remain separate.
