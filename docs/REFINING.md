# One-attempt NPC refining

**Inventory & skills → Refine one item** previews and submits one no-catalyst attempt on a currently observed, unequipped unique weapon or armor below +10. Open the refining dialogue manually in the game first. The controller requires its fresh prompt, the same observed NPC lifetime, a ready living character, settled movement, authoritative inventory/equipment/zeny, and exclusive action ownership. Observed own casts use the engine's shared availability fence, including retained stationary-input cooldown, for preview, commit and new initialization baselines. An elapsed cast duration, expired predicate, late adjustment or Stop cannot authorize an attempt; losing settlement retires a prepared preview. This is Companion settlement policy, not a claim that the server refine handler requires standing or freedom from all statuses.

Preview sends no game packet. It binds the target bag/item/GUID/count/refine/flags/four cards, inventory/equipment/currency revisions, own/NPC lifetimes and prompt generation. Raw unique identities stay private to the controller. The visible spending limit, zeny reserve, disposition budget/keep quantities and recovery/escape/ammunition reserves are validated from the current settings at both preview and commit. It does not use settings left behind by the last field run. Changing protected stock or the observed state requires another preview. Losing readiness, settlement or authority retires the token permanently, even if those values later recover. Trusted input in the official game also retires an unsent preview before any response arrives.

One explicit commit spends one ore and zeny. There is no desired-level loop, catalyst, implicit equip/unequip, replenishment, travel, routine, supply, profile execution or reconnect replay. These requests have dedicated native modes and are excluded from generic commands and automatic documents. They use the same native maintenance admission and bridge dispatch freeze as other manual actions. Updater settlement also requires the displayed preview/confirmation and every pending or retired economic receipt to finish or reconcile. Current-form persistence contains only settings and profile selection; refine targets, tokens and receipts are never saved or replayed.

An eligible failure lowers refine by one. The preview labels whether this is possible at the starting level. Metadata is generated from pinned source and matching public item identities; unknown or non-refinable items are unavailable. `RefineSuccess.csv` rows are consumed sequentially, as in the source loader: starting refine indexes the row, not its human-facing label. A threshold of 100 bypasses RNG; otherwise the source rolls integers 0–99 and fails only when the roll is greater than the threshold. The app does not mislabel the raw thresholds as success percentages. At starting +0 through +3, this source permits improvement only for every supported category.

A sent packet remains **pending** until all three effects match: exactly one ore removed, exactly the expected zeny debit, and the same unique item changed by precisely +1 or a source-permitted −1. The UI distinguishes **improved** and **downgraded**. The pinned server sends the same absolute currency readback twice; these identical readbacks are expected, not two debits. Effects, messages, cost-only evidence, unchanged refine, another GUID/cards/flags/count, or partial responses cannot prove the outcome.

Timeout, Stop, manual game input, NPC closure, map/death/character changes, or a socket error preserve unresolved economic ownership. No rollback, refund or retry is inferred. After Stop, a late exact receipt can reconcile a cancelled attempt without resuming anything. Trusted manual game input taints attribution because it can send a second economic request: sparse ore, balance and item receipts cannot release the owner after this interruption. Fresh full inventory/equipment and balance readback for the same character can reconcile current state while leaving the old outcome unknown. Readbacks from different lifetimes cannot be combined, and later sparse mutations retire a staged full inventory readback.

Retained refining ownership cancels automatic stationary cast recovery and excludes further Look probes, even after the NPC UI closes or the attempt is canceled. A source-qualified own Look, Walk, Counter ResetMotion or StopCast can settle cast availability without acknowledging ore, zeny or the unique-item outcome. A Look reply and its input cooldown do not qualify a new economic initialization or release an official refine hold.

Party rendezvous ownership and its retained canceled movement also exclude refining and new resource baselines. A canceled party Heal receipt remains an owner; even after exact Heal execution, refining waits for ordered own SP readback. Skill confirmation, timers and cast availability cannot substitute for that resource certainty. The original follow deadline still advances before an economic hold returns from the controller tick.

Normal ranged retreat ownership also excludes preview, commit and the separate economic initialization baseline, including after Stop while target clear or physical movement remains unresolved. Look and StopCast cannot retire that movement owner. An accepted shortened Walk must physically settle before admission returns; an unused retreat intent preserves its captured own-removal and map-arrival ordering. These movement receipts do not acknowledge refining outcomes or spending.

An official refine frame on an obsolete open game socket can retain economic uncertainty without canceling a skill already sent on the current socket. During that hold, the existing scheduler still advances the skill's original confirmation deadline and retires its controller receipt. Its bounded Stop cancellation can be sent; no new decision, Look probe or replay is admitted. This passive progress does not acknowledge refining or release its economic hold. The real bridge regression covers own actor IDs 0 and 1, with current-socket immediate cancellation as a separate control; it does not establish every routine or session clock.

An actual official-game refine submission (opcode 80) creates a separate admission hold before its original bytes are forwarded, including when Companion is idle. Ordinary pointer/key input does not create this hold. Because no request identifier or terminal acknowledgement identifies an arbitrary official attempt, sparse receipts and delayed same-connection full snapshots cannot release it. Ore may already have been consumed before a catalyst-validation failure; the unchanged NPC prompt and elapsed time prove no terminal result. Reopen the game with the same character: only after every owning old transport closes, a newer connection's first Enter, complete inventory/equipment/balance/skills initialization, and living own EnterServer spawn can reconcile current state. The exact resource revisions must still match; the baseline is consumed once and any intervening official command invalidates it. Stop, renewed prompts, map changes and timers cannot clear the hold. Nothing is retried or resumed, and the official outcome remains unknown.

**Advance / close refining dialogue** is a separate explicit button bound to the displayed prompt token. It calls the source-supported NPC advance path only when economic ownership permits. The NPC script determines whether this displays another prompt or closes. Stop cancels local intent; it does not close the server dialogue or undo spending.
