# NPCs and player shops on the live map

In **Bot → Live map**, ordinary NPCs appear as cyan diamonds. Hover a marker to see its name, NPC type and coordinates. Click the marker or its **Talk** button under **Nearby → NPCs** to request a conversation. The request opens **Tools → NPC dialogue**, where **Continue** and **Choose option** use the server's dialogue and menu observations.

Player shops appear as pink squares and have a separate **Nearby → Player shops** list. Click a square or **View shop** to request the seller's stock and open **Tools → Player vending**. The panel shows the server-confirmed shop name, seller ID, sale IDs, quantities and unit prices. Viewing never buys anything; purchases require an explicit choice of sale IDs and quantities. The player shop picker is separate from the NPC picker.

The distinction comes from observed NPC spawn metadata: a kind-2 actor with `npcSpawn.displayType = 3` is a vending proxy. Kind 4 is a player-like NPC, not evidence of a player shop, and remains eligible for Talk. Names, sprites and class IDs do not identify player shops. Missing or unsupported metadata retains the generic NPC behavior. The supported metadata layout is backed by the [public deployed client evidence](PROTOCOL.md#npc-display-and-player-shop-evidence), separately from any authenticated gameplay test.

Known NPC service labels come from the pinned service catalogue. Exact current-map, kind, name and anchor matches identify **Storage**, **Shop**, or **Teleport** services. Multiple contracts for one NPC combine their labels. Unknown or ambiguous matches remain **NPC**. Player shops are excluded from NPC service matching and preview evidence. These labels describe catalogue contracts, not proof that every deployed script has been exercised.

Manual Talk and View shop require a fresh living character, stopped automation and settled movement/actions. NPC HP zero and actor ID zero are valid. An actor without a published lifetime can be displayed but cannot be selected for an action. Nearby lists work on observed maps without collision data; map markers require the map raster. One combined hit test chooses the nearest NPC or player shop marker, with lower actor IDs breaking equal-distance ties. Shop square corners remain clickable. Empty map clicks retain the existing bounded Walk behavior.

Map and nearby clicks send command-only `manualNpcTalk` or `manualVendingView` envelopes containing the current map and the owner's and target's world, ID and incarnation. Native admission validates the envelope. The shared controller verifies both current actor lifetimes and the current NPC/shop classification before dispatching the existing opcode 76 `npcTalk` or 107 `vendingView`. Player shops never receive Talk: the pinned NPC click handler can enter a vending interaction without sending stock, blocking a later shop-view request. Opcode 107 targets the proxy NPC ID; its stock reply identifies the owner player, whose ID can differ. Existing receipt/focus correlation preserves that distinction.

A removed actor, reused ID, changed family/map/world, dead actor or stale observation cannot redirect a displayed selection. There is no automatic walking, dialogue advancement, retry, purchase or field-run intent. Raw NPC Talk and vending View remain compatible with current ordinary NPCs and confirmed vendors respectively. Opening a Tools panel acknowledges request admission; the summary only displays received stock.

Local verification covers deployed-layout fixtures and malformed known records, separation and unknown-metadata fallback, marker geometry, square corners and overlapping families, Talk/View versus Walk dispatch, actor zero, zero HP, stale/reused selections, locks, rejected dispatch, panel hooks, service matching, redraws, command validation, opcode bytes and receipt correlation. See `protocol.test.ts`, `bot-console.test.ts`, `feature-ui.test.ts`, `manual-npc-talk-logic.test.ts`, `controller.test.ts`, and the native `manual_npc_talk_is_strict_and_command_only` test. Offline UI and synthetic protocol checks do not establish a live deployed conversation, shop view or purchase.
