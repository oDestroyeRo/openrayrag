# Automatic client updates

The native client checks the public [SemVer release feed](https://github.com/oDestroyeRo/openrayrag/releases/latest/download/latest-semver.json) at startup and periodically. A newer canonical stable SemVer Apple Silicon macOS release is eligible, including minor and major upgrades. Only HTTP 404 permits fallback to the [legacy feed](https://github.com/oDestroyeRo/openrayrag/releases/latest/download/latest.json); other errors or invalid metadata retain the retry/error behavior. The legacy feed stays frozen at the signed compatibility release, so older clients install that bridge, restart, and then discover the SemVer feed. No GitHub token is stored in the client. The sidebar displays the running native version and platform. Windows, Linux and unsupported macOS architectures show manual-download status and never schedule, reserve or install the Apple Silicon archive.

Downloads run outside the game event loop. Metadata is capped at 64,000 bytes, the signed archive at 128 MiB, and archive expansion at 512 MiB with 10,000 raw records. GNU/PAX metadata is checked before tar can buffer it. A trusted public key verifies the archive and its authenticated version before it becomes an install candidate; completing a download progress callback is insufficient. Archive URLs must be the exact immutable repository/tag/version path. Links, special files, duplicate/case alias members, existing-file overwrites and unsafe modes reject. Both bundle version fields, identifier, executable architecture and strict Apple code signature must match. The main binary must also be owner-executable and required app directories owner-searchable; a code signature alone does not establish launchability. These updater signatures are separate from the current ad-hoc Apple signing; see [release publication](RELEASES.md).

## When installation is allowed

An update can suspend an active field run or macro. Suspension freezes new decisions and retains the original run intent while existing action receipts drain. Start/resume/Stop/manual command promises, login and reconnect, travel, workflow, routine, service, NPC/vending, movement, cast, equipment, economic, escape, supply, memo, socket, social, manual target and death-recovery owners must all settle. Sent actions with uncertain outcomes remain blockers. A workflow that requires further commands defers the update until it reaches a clean boundary. HP/SP recovery policy, a pure equipment policy fault or escape cooldown do not themselves own a sent action.

The final frozen acknowledgement captures exact counters and recovery guards. A private, versioned one-shot continuation preserves original deadlines, spent allowances, active character and macro selector/step/spend ledgers. It contains no password, transport packet or pending physical action. After successful signed replacement, a native launch token authorizes one claim in the new process. Normal launches, stale or corrupt files, wrong versions, wrong identities and duplicate claims cannot start automation. Settings storage remains a separate settings-only document.

Continuation reconnects only with an already-saved matching account. Otherwise it restores settings and waits for explicit Companion sign-in to the same account, slot, mode and verified character. Update downtime counts against finite limits. Exhausted limits stay exhausted; macros resume at a confirmed step boundary without replaying purchases or transfers. **Stop bot** is available during preparation and cancels continuation. Once replacement has begun, Stop prevents automatic continuation after restart. A failed installation releases the existing suspension; if the game has already closed, recovery waits for the matching saved account or explicit sign-in. Installed active-run continuation requires separate runtime proof from source and release checks.

The main form must be initialized, valid and saved. A nonempty unsent password or changed username/slot/remember/auto-login draft defers automatic restart; these drafts stay only in memory and never enter update settings. Clear the draft or explicitly sign in to consume it. Optional **Reconnect after connection loss · this session** remains a session preference and resets after app restart.

A native-generated nonce binds saved form revision, native command generation, game-window generation and page/socket identity. The bridge freezes inputs/transports, drains incoming work and gives a fresh positive acknowledgment. A native process also retains a conservative updater-only hold after any later game page replacement, close or reopen, independent of whether ready status was published. A clean replacement page cannot erase possibly lost receipt owners. Quit and reopen Companion when safe, or use the manual release download, to begin a new process; the updater never performs that restart for you. The first admitted initial page load remains eligible.

Native requests a second acknowledgment of the same owner revision immediately before commit. Incoming frames, socket replacement or navigation invalidate unsettled acknowledgment. A quiet connected map needs no arbitrary recent game packet: the fresh lease response establishes availability while all retained owners remain fenced.

Bot-only confirmation waits for an in-progress polling cycle to finish applying its batch, observing delivery and publishing status. The pending request retains its original owner revision; completing an empty poll can retry that request, while any incoming event or control mutation invalidates it. The final acknowledgment uses the same accepted owner. Waiting messages identify main-form blockers and explain that unavailable game confirmation will retry automatically.

All matching official game sockets, including obsolete instances and opaque payloads, and every Companion prototype transport are blocked during the held lease. Suppressed sends are discarded, never queued or replayed. Native gameplay/login entry points share the admission gate. Navigation mutex contention fails closed except for a one-shot native create/login/reconnect already admitted before a lease; its old identity is invalidated before queueing. Lease expiry or release never recreates an action; a canceled update may release its retained suspension in the same process. User Stop retires that intent first.

Committed install admission binds game retirement to the same nonce, game generation and socket identity. Native requires empty delivery/write queues and no connecting, joining or retired transport owners, then aborts and joins the settled transport outside both admission locks. Only the matching authorized window destruction preserves that lease. User closes, cancellation, new admitted frames and stale owners still invalidate it. Replacement requires completed transport retirement, consumed destruction acknowledgment and an absent game window. The game URL is queried before taking the maintenance lock because that query can dispatch to the UI thread.

No-game startup can update only after form restoration and the optional saved-login decision complete, and only if this process has never opened a game. Unexpected connection/page loss does not certify stopped state. After an official gameplay packet outside Companion ownership, availability is conservatively uncertain. Opaque/unsupported sends from a previously verified-ready game transport latch uncertainty synchronously before send, including obsolete sockets, without inspecting their bodies or taking over field controls. Known readiness/keepalive and cosmetic/social/query families remain inert. Every uncertain old transport must be observed closed before a newer connection delivers its first Enter, then full resource/skill/inventory initialization, then the exact matching own EnterServer spawn (`entryType=1`), with retained Companion owners settled. This restores availability only; it never confirms or retries the old request. The initialization is consumed once and any later possible gameplay send invalidates it. The open-transport tracker retains at most 32 owners; overflow keeps availability uncertain until a safe process restart. Same-socket map changes, timeout or page closure alone cannot reconcile it.

## Settings and replacement

Ordinary main-window Close and application Quit use a settings-save barrier: the controller cancels the edit debounce, waits for restoration and any current update preflight, serializes the latest valid form write, and acknowledges its saved revision before native shutdown. Controls remain locked during this operation; an already dispatched edit causes another flush. Duplicate requests share a token, Quit can promote an outstanding Close, and a failed save cancels the request with a visible error and permits retry. Reopening restores configuration without restoring run intent. Before the close listener registers, the form stays inert and native shutdown remains available. The updater's existing confirmed restart path bypasses this ordinary-close handshake.

On macOS, the application delegate's optional `applicationShouldTerminate:` method routes menu, Command-Q, and Dock Quit through Tauri's preventable exit event. The pinned Tao delegate otherwise terminates directly without that event. The bridge adds only the missing method to the actual delegate class, preserves the existing delegate and menus, and rejects incompatible registration at startup. Force Quit and process crashes cannot run this orderly-save handshake.

Current-form version 1 stores only strictly validated settings, logical configured map/target IDs, selected profile ID and a revision in native application data at `settings/current.json`. The file is bounded at 256,000 bytes, private (0700 directory/0600 file, no access ACL), and atomically replaced and read back. Version 0 settings-only documents have a bounded migration; unknown schemas/fields or corrupt documents defer updating. Structural/range checks also apply to a pristine offline form, while ordinary Start still requires a playable map/target configuration. Manual edits win a delayed restore, and serialized saves cannot overwrite a newer revision. Logical target selections survive empty/unready snapshots; current gameplay eligibility remains separate.

The form restores before optional auto-login. Named profiles and existing local login paths are unchanged, and no credentials, status, running intent or action history are persisted into this document. Profile selection restoration hydrates its name/summary without applying it or starting actions. Password storage and Forget retain the [local-login contract](LOCAL_LOGIN.md).

Installation never requests administrator privileges. An unwritable destination produces an error and the manual release link remains available. Its explicit click invokes one bundled-main command opening only the fixed public Releases URL, with no caller-supplied URL or general process permission. A private same-volume recovery cache uses a nonblocking interprocess lock; under that lock the on-disk version is reread so an older running instance cannot downgrade another instance's newer installation. Verified staged files/directories are synced before a macOS atomic exchange. The canonical `.app` path always contains an app across the exchange; a sync failure attempts another atomic exchange to restore the old bundle. At most one `previous.app` remains in `.rayrag-update-recovery` next to the installation. If rollback itself fails, the canonical path still contains the verified new app and the old app remains in that recovery path; the error does not promise which version remains canonical. No user app-data files are replaced.

A successful install restarts through Tauri's cached canonical executable path, carrying only a native one-shot update token. Settings restore first; a valid updater continuation waits for fresh matching character identity before resuming. Optional saved auto-login retains its ordinary-startup behavior. Network/signature/metadata/install failures keep bounded retry/backoff and expose state rather than retrying uncertain game actions.

## Bootstrap and proof surfaces

Older installed clients contain no updater and need one bootstrap installation of an updater-enabled app/DMG. Local developer app builds can disable only artifact signing with `npm run app:build -- --config '{"bundle":{"createUpdaterArtifacts":false}}'`; committed release configuration keeps artifact generation and signed-version enforcement enabled. Production signing keys belong only to root-managed release secrets.

Synthetic tests cover bounded/interrupted downloads, authenticated signature/version rejection, strict form persistence/migration and revisions, navigation/lease mutations, current/obsolete socket dispatch gates, retained movement/action owners, atomic replacement/rollback and interprocess locks. Source and local checks do not prove hosted release publication, an installed runtime update or successful restart. Those require separate CI/release and native runtime evidence; no test should induce a game death or restart a requested run.

### Installed updater verification, 2026-10-04

An installed v0.2.50 reproduced “Game settlement changed before replacement”: ordinary game-destruction cleanup invalidated the updater's own committed lease, even with an empty native transport. The retirement ownership correction above resolves that failure.

A local corrected bootstrap, explicitly stamped v0.2.54 for QA, was installed while Companion was closed with a recoverable copy of the previous app. This bootstrap was not an official v0.2.54 artifact. Its normal production updater downloaded the public signed v0.2.55 archive, closed the settled official game window, replaced the canonical application and restarted into a new process. The installed binary matched the public archive and passed strict code-signature verification. Saved settings and selected profile were identical before and after; only the persistence revision advanced. Saved auto-login remained independent of bot run intent. No bot run, death or economic action was initiated.

The restarted process completed startup and continued main/game IPC; the user confirmed its main window was visible after the UI tool lost its process attachment. This proves the With game client retirement/replacement/restart path.

A separate fresh Bot-only connection used a local v0.2.54 QA bootstrap containing the polling correction. Without starting a bot run, its production updater eventually obtained settlement, downloaded the signed public v0.2.55 archive, replaced that app and restarted into a new process. The resulting binary matched the public artifact and passed strict code-signature verification; logical settings and selected profile were unchanged. Busy polling and intervening frames deferred attempts instead of weakening admission. The UI tool again lost attachment after restart, so subsequent window interaction was not established by that tool. Native tests additionally cover pending transport tasks, completed joins, queued deliveries/writes, stale owners and cancellation during join. See [issue 65](https://github.com/oDestroyeRo/openrayrag/issues/65) for final release and subsequent installed-test evidence.
