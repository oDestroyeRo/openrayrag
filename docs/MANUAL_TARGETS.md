# Bounded manual movement and attack

The Workflows & social panel offers current-map destination coordinates and a visible living monster selector. Preview checks the current character, map collision data, portal exclusions, inclusive field rectangle, monster rules and equipped ammunition. Execute checks the actual world and actor lifetimes again. Known NPC/vending interactions, own casting, and sitting attacks are rejected before dispatch; a cast timer alone does not establish completion. A preview never sends a packet; an unavailable route or stale/replaced actor is rejected.

These are explicit, finite commands. They do not Start field automation, create reconnect intent, acquire replacement monsters, loot, cast attack strategies, switch equipment or use recovery items. An empty saved species selection is valid: selecting one observed monster authorizes that monster's species for this command only. Level, conditional attack/ignore rules, foreign engagement, HP, map restrictions, path cap, projectile sight and arrow reserve still apply. Configuration is captured from current controls, rather than a previous Start.

Opening panels with generic game input yields new decisions for two seconds while preserving the sent manual owner, accepted movement and absolute deadlines. A real official game command cancels the manual task and retains its receipt fences; it never resumes that canceled task. Panel input cannot postpone the whole-command deadline.

Walking uses collision-safe segments of at most 20 cells and one outstanding leg. Arrival requires accepted server movement, its timing and the requested endpoint; sending Walk is not success. Shortened or alternate server paths remain authoritative after collision/corner/portal checks. Unconfirmed legs, corrections, interruptions, world changes and deadlines terminate the task. There is no unconfirmed-walk retry.

An unresolved Walk from another controller owner also blocks manual admission. Only readback admitted for the captured manual character lifetime can reconcile a canceled manual leg through a shortened path or Stop; it does not clear another owner's movement ledger.

Normal Attack is a server engagement, not a single swing. The pinned `PacketAttack` handler can approach the monster and retain auto-attack. The command therefore keeps ownership after the first own Attack animation, until the selected monster's verified death, loss/ineligibility, Stop, or the whole-command deadline (1–120 seconds). Its approach also retains the configured approach deadline. Clear walking corridors permit a normal monster click to own the approach; obstructed corridors use the existing verified walking path. Only the selected lifetime is eligible.

## Cancellation and uncertainty

Pinned authority: Rebuild commit `4099e2c000c3c550516760b9c1241595aac9aceb`. `PacketStartMove` accepts two i16 coordinates and clears the current target; `PacketAttack` delegates to `Player.TargetForAttack`; `PacketStopAction` shortens movement and clears the target only when the character can act. Protocol packets have no request ID. These are source contracts, not proof of every deployed timing or action.

Stop is sent on cancellation/failure, but does not prove immediate server cancellation. An unacknowledged explicit Walk remains fenced until an authoritative self Walk or Stop, and any accepted shortened movement must finish before another owner can act. A retired normal attack requires acceptance for its captured monster lifetime followed by target clear. An earlier unrelated clear, elapsed timer, unrelated Attack, actor ID reuse or self death alone does not release an unaccepted attack. One additional Stop is allowed if the canceled attack is accepted late; no Attack is repeated. The canceled result remains canceled. Field Start, services and other manual owners are blocked while these receipts/movement are uncertain. A new connection resets the old transport's owner; it never restarts the manual command.

The wire cannot distinguish two otherwise identical replies by request identity. The controller prevents competing/newer requests while uncertainty remains, binds to observed world/incarnations, and reports pending evidence instead of treating a timeout as rejection. An unaccepted request remains uncertain across a map change on the same connection; a new actor incarnation cannot reconcile its old target or own movement/Stop replies. Character replacement or resurrection also creates a new observed lifetime, so old unconfirmed commands remain blocked until a fresh connection rather than draining through reused actor IDs. If no valid receipt can arrive, reconnecting creates a fresh transport without resuming the command. Native/TypeScript validation accepts this envelope only through the command boundary; routines and workflows cannot contain it. Task identities, previews and progress are ephemeral and never enter settings profiles.

For bows, verified compatible equipped arrows must be strictly above the configured reserve at preview and dispatch. An observed reserve or ammo fault sends Stop and blocks new attacks. Continuous server auto-attack and network delay mean shots already in flight can consume additional arrows before Stop arrives; this is not an absolute per-shot stock guarantee. Unknown stock never authorizes an attack, automatic switch or retry.

## Verification boundary

Focused fake-clock engine/controller tests cover segmented arrival, obstacles, diagonal corner and portal exclusions, ranges and sight, current field boundaries, target identity/eligibility, arrows, first/repeated attack animations, timeout, loss/death, Stop, late replies, trusted-input yield, reconnection and competing owners. A shared JSON corpus tests strict native/TypeScript validation and routine exclusion; DOM callback tests exercise selection lifetime, policy extraction, preview, malformed input, progress and Stop. Native packaging is local build evidence. Live gameplay validation is a separate delivery check.
