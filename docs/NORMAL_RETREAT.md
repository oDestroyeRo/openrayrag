# Bounded normal attack retreat

In **Combat & loot**, **Retreat during verified ranged normal attacks** is off by default. It applies to an already observed normal Attack against one monster lifetime. It does not retreat during a skill strategy or a bounded manual attack.

The five configuration values are an optional `automation.retreat` object. Old profiles omit the object and retain current behavior; applying a profile never starts automation.

| Value | Default | Bounds and meaning |
| --- | --- | --- |
| `enabled` | false | Opt in to this policy. |
| `triggerDistance` | 2 | Integer 1–13; retreat may start at or below this separation. |
| `desiredDistance` | 5 | Integer 2–14, strictly above the trigger; it must fit the currently verified normal attack range. |
| `maxPathSteps` | 12 | Integer 1–20; cumulative dispatched steps in one retreat cycle, including replans. An accepted longer detour consumes additional allowance and cancels when over budget. Shortened movement does not refund dispatched steps. |
| `maxAttempts` | 3 | Integer 1–10; counted on the first Walk dispatched in a cycle, per actual observed monster lifetime. |

Separation uses the pinned rounded float32 Euclidean normal-attack metric. The weapon, learned bow range modifiers, current visibility limits and arrow stock must be verified. Melee or unknown range leaves retreat unavailable. Arrow compatibility and the configured minimum observed ammo reserve apply even with automatic loadout switching disabled. Retreat never equips gear or refills ammo itself. Already in-flight shots can consume stock before Stop reaches the server.

The local planner enumerates at most 841 cheap coordinates in the current firing radius, inspects the first 128 for safe ground and projectile sight, and plans at most 32 viable candidates. Candidates increase separation, meet the desired distance and remain valid firing tiles. Initial ordering is movement lower bound, greater separation, then y/x. Final selection uses verified 10/14 movement cost, greater separation, then y/x. This bounded search may report no candidate despite an unexamined alternative; it is not an exhaustive global escape optimizer.

Routes use physical walkability, diagonal side checks, portal exclusions, temporary blocks and the inclusive field lock area. Projectile sight remains separate from walking permission. Each leg revalidates the same joint own/target lifetime, target position, field, effective range, ammo and remaining path allowance. One movement request is outstanding at a time.

The sequence is normal Attack observed → Stop → authoritative target clear and previous movement settlement → explicit Walk → accepted route timing and endpoint settlement → normal Attack against the same still-eligible monster. The first attack animation establishes engagement; neither dispatch nor predicted arrival manufactures success. No alternate monster, loot, skill, or resource action is dispatched while retreat owns settlement. Existing recovery, resource, strategy and emergency escape priorities cancel the retreat first and then wait for its physical owner to settle.

The initial normal engagement's 90-second limit and 12-second no-progress limit survive retreat, reattack, target switches and same-world Stop/Start. Only matching own normal Attack observations update progress. The movement episode starts on the first retreat Walk and retains the existing `attackMaxRouteTime` through replans and panel input. Attempt budgets live in a non-evicting ledger of at most 300 observed monster lifetimes. No-path, exhausted allowance or deadline failures skip the actor for the existing 30-second cooldown while retaining field intent.

Retreat shares the engine’s observed own-cast admission fence. Predicted expiry, an unresolved extension, or an ambiguous triggered result is not completion. Source-backed own cast completion or accepted own walking can prove availability without acknowledging a resource action or an explicit retreat walk. Unknown spawn casting alone is not invented as an active cast. Cast uncertainty, input-delay debt from stationary availability queries, and retreat movement have separate owners; settling one does not release the others. Active or retired retreat settlement suppresses automatic availability queries, including when waiting for target clear without motion. A valid own Look or CastStop never acknowledges an explicit retreat Walk. See [cast availability](CAST_AVAILABILITY.md).

Stop, target loss/replacement, death, world change and real game commands cancel retreat intent. Generic panel input yields decisions while movement and deadlines continue. A sent Walk with an unknown outcome remains a retired owner; elapsed time and an unrelated Attack cannot acknowledge it. Matching current-own Walk/Stop readback, fresh target clear and accepted movement settlement reconcile it. If the original own world/incarnation changes, old receipts cannot settle it; a fresh transport is required. This can hold automatic death recovery when movement is genuinely uncertain. A matching current-own Death retires only an unsent retreat intent with no explicit, implicit, or accepted movement remaining; the pinned Player.Die clears its target before emitting Death. The original ledger, counters and death cap remain intact, and the existing finite respawn owner may proceed. Duplicate or foreign Death cannot retire a physical hold. Once canceled, that retreat never resumes.

An ordered map transfer or same-map Warp can retire an unsent retreat intent only after observed old-lifetime target clear, no explicit, implicit or accepted movement, and matching living own arrival. The server removes the own actor before the transition: map transfer emits OutOfSight removal (reason 0), target clear, then ChangeMaps; an earlier Stop may already have cleared the target. Same-map Warp emits target clear, own removal (OutOfSight 0 or Teleport 1), RemoveAllEntities, then Warp entry 2. The client captures physical absence while the original living own lifetime still exists. A later target-clear packet carries no actor ID, so it can bind only to that captured old world, own ID and incarnation while the actor remains absent. Map transfer requires entry 1; Teleport reason 1 permits only the same-map Warp transition. ID, name, player kind and destination map must match the captured arrival. A matching HP0 arrival grants no readiness. A different own name/kind, unexpected own entry, replacement before transition, or another transition revokes the capture. Foreign actors are irrelevant. Missing target clear and every sent or accepted physical hold remain unresolved. This does not acknowledge a resource action or replenish a run budget.

The wire has no Walk/Stop request IDs. A delayed same-lifetime Attack after an earlier clear therefore requires another clear; at most one additional Stop is sent. Invalid or locked returned movement is not confirmation. The status explains whether Walk/Stop readback, target clear, accepted movement, or a fresh connection is missing. No uncertain Walk is retried.
