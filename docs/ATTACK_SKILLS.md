# Attack skill strategies

The optional `automation.attackStrategies` list is empty or omitted by default. Ordinary attack routing and its search counts remain unchanged in that mode. Strategies apply only to eligible species selected by existing combat rules, ownership and level/radius guards. They do not authorize attacking another species.

```json
{"id":"poring-opener","speciesIds":[4000],"skillId":11,"level":3,"behavior":"opener","maxAttempts":2,"maxUses":1,"cooldownSeconds":3}
```

Rules use stable IDs (1–48 ASCII letters, digits, `_` or `-`), 1–64 unique positive species IDs, skill 11/12/16, level 1–10, `opener`/`repeat`, attempts 1–100, uses 1–attempts and cooldown 1–3600 seconds. At most 32 ordered rules are allowed. Optional actor predicates use the shared schema; candidate scope remains exclusive to monster eligibility rules. Earlier applicable rules win; two rules can use the same skill with independent limits. Known-false conditions skip that row, while unavailable selected prerequisites hold it rather than falling through to an ordinary attack. The UI can move rows earlier/later.

An opener runs before this controller's first dispatched normal attack on the observed actor. Normal dispatch history is retained even while strategies are disabled, so enabling an opener cannot reopen an already attacked actor lifetime. It does not prove that a monster was untouched by others. Per-rule attempts are reserved only when the action owner dispatches the cast; route selection and walking do not spend attempts. A use is counted once only after matching direct execution (source, skill, level, mode and actor). A→B→A switches, temporary pauses and Stop/new Start in the same world retain counts. New actor incarnation, removal/death or world reset invalidates them. A bounded ledger never evicts a live spent allowance to make room for a new actor.

Rejection spends an attempt, records a failed rule and does not count a use. Timeout, send uncertainty or canceled cast retains an unresolved tombstone on the original rule/actor lifetime. Stop/Start cannot silently retry it or credit a late result. Existing scheduler/controller deadlines still fence the outstanding action. The wire has no request ID; arbitrary identical late frames after a new actor incarnation cannot be perfectly correlated. Socket/world and local incarnation ownership provide the available bounds, not impossible wire-level guarantees.

An exact late execution can settle a canceled controller receipt without restoring its strategy allowance. Before releasing that receipt, the shared action timer retains the greater of observed spell motion and the verified after-cast delay. Supply, emergency escape and other actions observe the same timer, including when the original response deadline has elapsed. Nonmatching ground coordinates leave the original receipt unresolved.

Unknown opener prerequisites wait up to 30 seconds, then skip that actor for 30 seconds with a reason while retaining field run intent. The opener window stays open. Existing walk acknowledgment and pursuit deadlines continue during unavailable prerequisites without authorizing a new walk or cast. A new actor pursuit starts its own clock after any inherited leg settles; switching targets does not borrow a search or another actor's timer. A matched repeat rule can preempt an owned normal attack only by sending Stop, settling motion and (when loadout ownership is enabled) observing authoritative target-clear 33. Pending pickups and chosen pickup routes settle before a strategy can take ownership. Pending/uncertain equipment receipts, recovery, travel, routines/workflows and emergency escape remain with their existing owners. Strategy code never changes equipment or replenishes supplies.

## Verified policies and source

Authority is Rebuild `4099e2c000c3c550516760b9c1241595aac9aceb`; the public pin does not prove every deployed-server detail. OpenKore `51de1ddfc4449ae5217f6886de702f87ca934030` `AI/Attack.pm:725–758,1061–1064` is only a behavior reference for ordered rules/dispatch attempts. No upstream architecture or implementation is copied.

Automatic actor policies cover Fire Bolt 11, Cold Bolt 12 and Lightning Bolt 16. `Simulation/Skills/SkillHandlerAttribute.cs`, `SkillHandler.cs:143–155` and Mage `TargetedSpellBase.cs` establish magic range 9, Blind cap 5, level-adjustable casts and a direct one-second after-cast delay. Paths reach a safe casting tile using rounded float32 Euclidean distance and directional projectile sight. Normal click-to-chase shortcuts are never used for casts. Movement legs settle before identity, eligibility, conditions, permission, range, LOS and effective SP are revalidated immediately before dispatch. Moving targets and range changes retain the original pursuit budget.

Manual Thunderstorm 19 uses range 9/Blind 5 and the same stationary LOS checks; an out-of-range request is rejected without an automatic route. Its destination needs an in-bounds coordinate and LOS, not a walkable ground tile. Mage `ThunderStormHandler.cs` establishes a 5×5 area and 1.5-second after-cast delay. Its direct result must confirm the exact requested coordinate. Automatic ground AoE is excluded because filtering the center would not constrain affected actors. Other manual skills retain the existing conservative adjacent behavior. Combos, ammunition-dependent casts, kiting and party support remain unsupported.

Supported body-state observations must prove absence of Stun, Sleep, Frozen, Silence, Petrifying (Pacification), Stone and Hiding; Blind must be known. Refresh gaps and predicted expiry are unavailable for either sign. Observed learned/granted permission and sufficient effective SP are required. The scheduler proves its own cast/motion ownership; spawn has no server cast replay. Known observed active casts block dispatch. Server-only input cooldown, disabled/NPC state or an unobserved external cast can still reject or silently discard the request, so local readiness is not a claim that every server prerequisite is observable. An explicit casting predicate remains unavailable without fresh cast evidence. Rejection and timeout are conservative and never imply successful use. Pinned PacketStopAction does not cancel an active cast, so local Stop retains the cast receipt deadline and unresolved strategy tombstone; it is not evidence that server execution was canceled.

Effective SP follows `EntityComponents/Player.cs:1212–1217` integer arithmetic: base cost × (100 + SpConsumption) / 100. `scripts/build-cast-policy.py` validates pinned code→item identity and current public names, audits all six modifier declarations and records source hashes. It does not execute scripts. Known effects are Vitata +15%, Golden Thief Bug +100%, Pharaoh −30% per installed card, Staff of Destruction +2% per refine, and each complete Ninja Suit/Shinobi Sash combo −30%. `ItemEquipState` applies canonical bag items, each of four installed card slots and each active combo once. Missing/unknown unique metadata, unknown installed cards/equipment or a negative SP multiplier returns unavailable before truncation (including a small negative product that would otherwise round to zero). Internal slots/GUID are used for derivation and remain excluded from public inventory telemetry. Incoming 63 socket/refine mutation checks identity before replacing metadata; mismatch requires a fresh inventory. Gear and grant receipts are consumed before recomputation.

Regenerate with `python3 scripts/build-cast-policy.py /tmp/rayrag-public-protocol /tmp/cast-policy.json` and compare bytes to `src/data/cast-policy.json`. Source-shaped synthetic tests are local proof. Native UI/unlearned gates and ordinary combat are separate proof; these fixtures do not establish live execution on an account without the supported learned spells.

## Native validation

On 2026-10-02 the signed local macOS build completed login with credentials kept in memory. The native strategy editor accepted selected map species and a bounded Fire Bolt opener. With no learned bolt, live encounters displayed the required learned/granted-level reason, retained run intent and showed the 30-second wait/skip policy without attacking. Removing the strategy restored ordinary combat immediately; the controlled run recorded seven defeated monsters and 17 confirmed pickups before Stop returned Ready and app exit was verified. No profile or credentials were saved. This proves the UI, unavailable-skill gate and default combat path, not live bolt execution, moving-target casting, repeat casts or SP-modifying equipment. The final package was rebuilt with the default new rule using this game's Poring species ID `4000`.
