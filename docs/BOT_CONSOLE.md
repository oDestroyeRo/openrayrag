# Bot console

The app opens to the console. Its persistent monitor shows observed HP/SP, base and job levels, weight/capacity, zeny and EXP totals/gains. Missing observations show a dash; EXP percentages are not inferred. Start, Stop, connection state and the current wait reason remain outside the page tabs.

Connect account opens the retained account/character form. Sign in creates the fixed official game page in a hidden WebKit window. Existing build compatibility, login claims, native capabilities, navigation generations and maintenance gates remain in force. The Unity renderer and bridge still run: this is a console interface, not a new direct network transport. Hidden macOS WKWebView background liveness has not been established by synthetic checks; the change does not alter Unity's loop or browser DOM.

Stop automation and let outstanding actions settle before manual controls. Clicking the collision map sends one bounded current-map walk through the existing manual-target controller. X/Y coordinates provide the keyboard equivalent. CSS scaling and map Y orientation are accounted for. Unknown maps, blocked cells, portal exclusions, unreachable routes, stale identities and field-policy violations reject the request. Nearby Attack binds the observed monster lifetime and uses the same current settings/preview path. It never silently stops or resumes the bot.

Inventory choices use observed stock and the pinned item catalog. Use one item admits only an untargeted usable item; targeted items, skills and equipment remain in Manual tools. No arbitrary target is selected. A requested item remains explicitly unconfirmed in the console because native invocation does not identify a receipt. Latest controller action results are displayed separately and are not attributed to that item. Latest bounded-command telemetry is likewise distinct from the current request message. Ground drops are displayed without a raw pickup shortcut; bot pickup uses the configured loot policy and controller receipts.

Page navigation retains settings and tool nodes, coordinate drafts and selected inventory choices without sending a command or saving settings. Connection loss, stale status, login, pending requests, unresolved owners and updater installation lock manual controls immediately. Disconnect is explicit and disabled while the client observes active automation or pending action owners. It closes the hidden connection so another account/character can be selected; it does not undo server actions or prove every server-side action settled. Closing the main app destroys its hidden runtime through the existing window lifecycle handler.

Focused tests exercise coordinate edges/Y orientation, route policy, actor zero and replacement, stale observations, retained controls, inventory admission, honest result labels and main-window locks/disconnection. Native source/build tests cover the restricted command boundary. Actual app launch, hidden-runtime gameplay liveness, account changes and live item/walk/attack receipts remain separate runtime verification.
