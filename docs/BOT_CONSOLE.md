# Bot console

The app opens to **Run**, with observed activity on the left and the live collision map and Nearby/Inventory inspector on the right. **Setup**, **Tools** and **Settings** retain the existing forms. Edit setup only opens Setup; the summary reflects the current form, not a newly started run. The persistent monitor shows observed HP/SP, base and job levels, weight/capacity, zeny and EXP totals/gains. Missing observations show a dash; EXP percentages are not inferred. Start, Stop, connection state and the full current wait reason remain above every page. During a run, Stop is the primary action; Start returns when the run is stopped or waiting.

Connect account opens the retained account/character form. **Bot only** signs in through one fixed native TLS WebSocket and runs the existing controller in a bundled local webview without loading Unity. **With game client** opens the official **Game** view in the same desktop window, with its existing bridge and input handling. Switch between **Game** and **Bot** without signing in again or changing the current run; Start and Stop remain explicit. Both modes keep build compatibility, current action policies, bounded receipts, native capabilities, navigation generations and update gates. Disconnect before changing connection modes. See [connection modes](CONNECTION_MODES.md) for evidence and limitations.

Stop automation and let outstanding actions settle before manual controls. Clicking the collision map sends one bounded current-map walk through the existing manual-target controller. X/Y coordinates provide the keyboard equivalent. CSS scaling and map Y orientation are accounted for. Unknown maps, blocked cells, portal exclusions, unreachable routes, stale identities and field-policy violations reject the request. Nearby Attack binds the observed monster lifetime and uses the same current settings/preview path. It never silently stops or resumes the bot.

Inventory choices use observed stock and the pinned item catalog. Use one item admits only an untargeted usable item; targeted items, skills and equipment remain in Manual tools. No arbitrary target is selected. A requested item remains explicitly unconfirmed in the console because native invocation does not identify a receipt. Latest controller action results are displayed separately and are not attributed to that item. Latest bounded-command telemetry is likewise distinct from the current request message. Ground drops are displayed without a raw pickup shortcut; bot pickup uses the configured loot policy and controller receipts.

Page navigation retains settings and tool nodes, coordinate drafts and selected inventory choices without sending a command or saving settings. Inspector tabs, Edit setup and Account remain available during an update; actual action inputs stay locked. Map details & coordinates groups collision counts and the keyboard form; submitted map/attack feedback and observed bounded-command results remain visible outside it. Connection loss, stale status, login, pending requests, unresolved owners and updater installation lock manual controls immediately. Disconnect is explicit and disabled while the client observes active automation or pending action owners. It closes the selected connection so another account/character can be selected; it does not undo server actions or prove every server-side action settled. Closing the main app destroys its hidden runtime through the existing window lifecycle handler.

Focused tests exercise coordinate edges/Y orientation, route policy, actor zero and replacement, stale observations, retained controls, inventory admission, honest result labels and main-window locks/disconnection. Native source/build tests cover the restricted command boundary. Local synthetic WebSocket tests cover the actual native socket loop; runtime and form tests cover packet ordering, initialization, mode persistence, Stop and update fences. Actual account acceptance, background macOS gameplay liveness and live item/walk/attack receipts remain separate verification.
